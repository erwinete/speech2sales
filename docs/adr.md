## Лицензирование и open-source стратегия

### Проблема

Ядро — open-source (канал дистрибуции и доверия), монетизация — отдельный SaaS-тренажёр. Нужно: (1) не дать конкурентам закрыть/захостить ядро без вклада, (2) не отпугнуть интеграторов и корпоративных пользователей, (3) оставить формат и сценарии свободными навсегда.

### Решение (трёхслойное)

| Слой | Лицензия | Почему |
|---|---|---|
| Ядро платформы (`polylog-core`, включая API, воркеры, UI) | **AGPLv3** | закрытая SaaS-обвязка над ядром без публикации исходников невозможна — защита основной бизнес-угрозы; для МСБ-заказчика AGPL не барьер (они не дистрибутируют) |
| Спецификация обменного формата + JSON-схемы + примеры | **CC0 / CC-BY-4.0**, отдельный репозиторий | стандарт должен быть свободен от копирайт-рисков, иначе не станет стандартом; `license` поле сценария — CC-BY-4.0 по умолчанию |
| SaaS-тренажёр | **проприетарный** | монетизация; обменивается с ядром только через CC0-формат |

### Последствия и оговорки

- Интеграторы, желающие поставлять закрытые дополнения (свои коннекторы в своих репозиториях, динамическая загрузка через plugin SDK), формально не обязаны открывать код — плагин-контракт через entry-points в AGPL-процессе остаётся серой зоной; фиксируем: **plugin SDK API задокументирован как граница**, подключение отдельных не-производных модулей разрешено. Требует консультации юриста (пометка в ADR-10).
- Роадмап-опция: «commercial license» для заказчиков, которым AGPL неприемлем (двойное лицензирование) — решение отложить до первых корпоративных пилотов.
- Все сторонние модели используются в соответствии с их лицензиями; лицензии фиксируются в `models_registry` и показываются при активации.

## Что дальше (перед разработкой, по решению 2026-10-03)

1. Принять гейты InfoBayAI и верифицировать датасет по чек-листу ([doc 06](06-datasets.md) §1.1) — от наличия транскриптов зависит план эталона распознавания.
2. Скелет репозитория: monorepo (`core/`, `web/`, `spec/`, `tools/devstand/`), CI (ruff, mypy, pytest, pip-audit, spec-фикстуры), pin окружения (Python 3.12, PyTorch cu128 под Blackwell RTX 5060, ONNX Runtime).
3. Dev-стенд: профиль `devstand` (Asterisk + инжектор звонков из датасета), приёмочные S1–S3 ([doc 09](09-dev-stand.md)); в M2 — nightly-регресс S6.
4. Эталон распознавания из датасета (транскрипты ± ручная сверка/доразметка 3–5 ч) → бенчмарк GigaAM-v3 vs T-one vs Whisper (WER, RTF на RTX 5060, INT8-CPU) — зафиксировать выбор дефолта в ADR-4.
5. Юридическая проверка AGPL-позиций и plugin-границы — **отложена** (ADR-17); провести до публичного релиза и публикации весов.
